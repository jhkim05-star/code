# 앱 모음

이 저장소는 정적 웹앱 여러 개를 하위 경로로 나눠 담습니다.
빌드 도구·서버·계정 없이 GitHub Pages 하나로 전부 서비스됩니다.

| 경로 | 앱 | 설명 |
|---|---|---|
| [`/reading/`](reading/) | 책꽂이 · 기록 | 읽는 책·읽은 책, 본 영화·드라마를 남기는 독서·감상 노트 |
| [`/workout/`](workout/) | 운동일지 | 혼자 하는 웨이트를 위한 계획·실행·기록 |

루트의 `index.html`은 두 앱으로 가는 링크만 있는 런처 화면입니다.
각 앱은 코드·기능 면에서는 완전히 독립적입니다.

### 저장 공간에 대한 주의

두 앱은 같은 GitHub Pages 도메인(같은 오리진) 아래 있습니다. 브라우저의
`localStorage`는 **경로가 아니라 도메인 단위**로 묶이므로, `/reading/`과
`/workout/`은 저장 공간 자체는 같은 통을 씁니다. 지금은 두 앱이 서로 다른
키(`bookshelf.data.v1` / `wl:*`)를 쓰고 각자의 "전체 삭제" 기능도 자기 키만
지우도록 되어 있어 **데이터가 서로 섞이거나 덮어써지지는 않습니다.** 다만:

- 사파리에서 **이 사이트의 웹사이트 데이터를 지우면 두 앱이 동시에** 사라집니다
  (도메인 단위 삭제이기 때문입니다). 한쪽 앱만 초기화하고 싶을 때는 반드시
  그 앱 안의 "전체 삭제" 버튼을 쓰고, 사파리 설정에서 지우지 않습니다.
- 새로 추가하는 앱이 있다면 `localStorage` 키 접두사가 기존 앱들과
  겹치지 않는지 반드시 확인합니다.
- 저장 공간 총량(보통 오리진당 수 MB)도 두 앱이 나눠 씁니다.

각 앱의 설치 방법·기능·데이터 구조는 해당 폴더의 README를 봅니다.

## 배포

`.github/workflows/pages.yml`이 `main` 브랜치 푸시마다 저장소 전체를
GitHub Pages로 그대로 올립니다. 저장소 **Settings → Pages → Source**를
**GitHub Actions**로 한 번만 바꾸면 이후 자동입니다.

## 새 앱을 추가하려면

1. `/<앱이름>/` 폴더를 만들고 그 안에서 완결된 정적 앱으로 개발합니다
   (그 폴더 안의 파일들만 상대경로로 참조하도록 만들면, 나중에 폴더째
   옮기거나 다른 저장소로 떼어내도 그대로 동작합니다).
2. 루트 `index.html`의 목록에 카드를 하나 추가합니다.
3. 이 표에 한 줄 추가합니다.
