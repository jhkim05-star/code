# 월간 독서·영상 기록 정리

「책꽂이 · 기록」 앱의 내보내기 파일을 받아, 그 기간에 무엇을 읽고 보았는지
한눈에 들어오는 보고서로 정리한다.

읽는 사람은 본인이다. 자기 기록을 나중에 다시 펼쳐볼 때 쓸모 있으려면
**숫자가 정확해야 하고, 기록에 없는 말이 섞이지 않아야 한다.** 이 두 가지가 이 작업의 전부다.

## 작업 순서

### 1) 입력 파일 확인

지원 형식은 세 가지다. 어느 것이든 그대로 넘기면 된다.

| 파일 | 담긴 내용 |
|---|---|
| `독서영상기록_*.xlsx` | 책·비디오장·기간별 통계·분포 4개 시트 (가장 완전함) |
| `독서기록_*.csv` / `영상기록_*.csv` | 책 또는 영상 한 종류만 |
| `기록백업_*.json` | 앱 원본 필드 그대로인 전체 백업 |

파일을 못 받았으면 먼저 물어본다. 앱에서 **설정 → 내보내기**로 받는다는 점을
알려주면 사용자가 바로 가져올 수 있다.

### 2) 집계 — 반드시 스크립트로

```bash
python3 scripts/summarize.py <파일경로> [--month 2026-09 | --week 2026-W36] [--out summary.json]
```

- 기간을 주지 않으면 기록이 있는 **가장 최근 달**을 고른다.
- 파일을 여러 개 넘겨도 된다(`책.csv 영상.csv`). 겹치는 기록은 알아서 걸러낸다.
- 표준 라이브러리만 쓰므로 openpyxl 설치가 필요 없다.

나오는 JSON 에는 보고서에 필요한 값이 전부 들어 있다.
권수·쪽수·평균 별점·평균 독서기간·최장/최단·장르 분포·국내외·종이책 여부·
영상 편수와 시청 시간·플랫폼, 그리고 **전 기간 대비 증감**과 읽는 중·대기 목록까지 나온다.

**합계와 평균을 직접 계산하지 않는다.** 항목이 열 개만 넘어가도 사람이든 모델이든
암산이 어긋나고, 어긋난 숫자는 기록으로서 쓸모가 없어진다. 스크립트가 낸 값을
반올림 자리까지 그대로 옮긴다.

집계 결과가 비어 있으면(그 달에 완독·시청 기록이 없으면) 보고서를 억지로 만들지 말고,
기록이 없다는 사실과 그 기간에 읽는 중이던 책을 알려주는 편이 낫다.

#### 잘못 읽기 쉬운 값

| 필드 | 뜻 |
|---|---|
| `videos.total_episodes` | 영화 1편 + 시리즈 화수를 **합한 총 회차 수**. 개별 시리즈의 화수가 아니다 |
| `videos.items[].episodes` | 그 작품 하나의 화수. 시리즈별 화수를 쓸 때는 이 값을 본다 |
| `videos.series_count` / `movie_count` | 시리즈 작품 수 / 영화 작품 수 |
| `books.pages` | 그 기간에 **완독한** 책의 쪽수 합. 읽는 중인 책은 빠져 있다 |
| `delta.*` | 직전 기간 대비 증감. 음수면 감소 |

시간은 분 단위 원값과 함께 `minutes_label`(예: `"10시간 14분"`)이 들어 있으니
직접 나누지 말고 그대로 옮긴다. `delta.minutes_label` 은 증감의 절댓값이므로
늘었는지 줄었는지는 `delta.minutes` 의 부호로 판단한다.

### 3) 보고서 작성

**작성 전에 `references/report-format.md` 를 읽는다.** 항목 기호 계층(`□ ○ - ·`),
명사형 종결(`~함`, `~임`), 날짜 표기(`2026. 9. 3.`), 표 만드는 법, 붙임 처리가
예시와 함께 정리되어 있다. 문체가 흔들리면 보고서 전체가 어색해지므로 매번 확인한다.

기본 뼈대는 이렇다. **그 기간에 내용이 없는 장은 통째로 뺀다.**
'해당 없음'으로 남겨두면 훑어보는 데 방해만 된다.

```
Ⅰ. 개  요        대상기간 · 자료출처 · 정리내용
Ⅱ. 기록 현황     총괄 수치 + 전월 대비 비교표
Ⅲ. 완독 도서     책별 서지 · 독서기간 · 별점 · 한줄평 · 독서록 간추림
Ⅳ. 시청 영상     작품별 정보 · 시청일 · 별점 · 한줄평
Ⅴ. 특  징        분야 / 국내외 / 독서 형태 / 진행 중
```

### 4) 결과 전달

기본은 마크다운 파일(`'26년 9월 독서기록.md` 처럼 기간이 드러나는 이름)로 저장하고
본문도 대화에 보여준다. 사용자가 문서 파일을 원하면 `docx` 스킬로 변환한다.

## 지켜야 할 선

**기록에 없는 감상을 지어내지 않는다.** 이것이 가장 중요하다.
한줄평이 비어 있으면 그 줄을 빼면 되고, 독서록이 없으면 '소회' 항목을 만들지 않는다.
읽지 않은 책의 내용을 일반 지식으로 채워 넣는 것도 마찬가지다.
나중에 본인이 다시 읽었을 때 '내가 이런 생각을 했었나' 싶은 문장이 섞여 있으면
그 기록은 신뢰를 잃는다.

**독서록은 간추리되 표현은 살린다.** 긴 독서록은 두세 줄로 줄이는 게 맞지만,
본인이 쓴 인상적인 표현이나 인용한 문장은 그대로 옮긴다. 요약하느라 밋밋해지면
정리한 의미가 없다.

**해석은 근거가 있을 때만 붙인다.** "국내서 비중이 높음"은 숫자에서 나오지만,
"한국 문학에 대한 관심이 깊어짐"은 세 권 표본에서 나올 수 있는 말이 아니다.
표본이 작으면 집계만 적고 해석은 생략한다.

## 요청 변형에 대응하기

- **주간 정리** — `--week 2026-W36`. 제목과 대상기간만 주 단위로 바꾸고 틀은 같다.
- **분기·연간 결산** — 해당 월을 각각 돌려 합친다. 이때 장르·국내외 분포는
  전체를 다시 세야 하므로, 달마다 나온 `genres`·`origin` 목록을 합산해서 쓴다.
  기간이 길면 Ⅲ·Ⅳ장의 작품별 서술은 별점 높은 순 상위 몇 편으로 줄이고
  나머지는 붙임 목록으로 돌린다.
- **특정 분야만** — "올해 읽은 기술서만" 같은 요청은 집계 JSON 의 `items` 에서
  `genre` 로 골라낸 뒤 그 부분집합으로 Ⅲ장을 쓴다. 총괄 수치는 전체 기준인지
  골라낸 기준인지 보고서에 분명히 적는다.
- **비교 요청** — "작년 9월이랑 비교해줘"처럼 두 기간을 대볼 때는 각각 집계를 돌리고
  Ⅱ장의 비교표에 열을 하나 더 붙인다.

## 파일 구성

```
scripts/summarize.py          기간별 집계 (표준 라이브러리만 사용)
references/report-format.md   개조식 표기 규칙과 보고서 예시 — 작성 전에 읽을 것
```
