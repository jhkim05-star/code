# 우리 집 대모험 — 1장 (Chapter 1 버티컬 슬라이스)

Phaser 4 + TypeScript + Vite로 만든 가족 코미디 세계관의 덱빌딩 로그라이크입니다. 메커니즘은 이 장르의 익숙한 문법(공격/방어/스킬/파워 카드, 희귀도, 강화, 기합·유연함·위축·빈틈·잔소리·정색 같은 버프/디버프, 노드형 맵, 상점·휴식·사건)을 그대로 따르고, **이름·세계관·소재로만 차별화**합니다.

```sh
npm install
npm run dev
npm run build
```

개발 서버 주소는 터미널에 표시됩니다. 가로 화면 기준 960×540 게임 영역이 화면에 맞춰집니다(Phaser Scale Manager `FIT` + `CENTER_BOTH`).

## 세계관

플레이어는 몸이 작아진 채로 "우리 집"을 뚫고 나가야 하는 막내다. 거실·부엌·옷장 곳곳에 쌓인 집안일과 잔소리가 몬스터가 되어 앞을 막는다. 최종 보스는 "정리정돈의 수호신". 카드 이름(베개 스매시, 이단 옆차기, 잔소리 시전 등)과 상태 효과 이름(기합/유연함/위축/빈틈/잔소리/정색)이 전부 이 세계관과 연결되어 있다.

## 구조

```
src/
├─ main.ts                 Phaser 부팅, 모든 Scene 등록, 새 런 생성
├─ scenes/                  화면 표시·입력·씬 전환만 담당(게임 규칙 없음)
│   ├─ theme.ts / ui.ts / shared.ts   공용 색상·버튼 헬퍼·런 상태 레지스트리
│   ├─ MapScene.ts           맵: 현재 층 선택지 표시, 노드 선택
│   ├─ BattleScene.ts        전투 화면
│   ├─ RewardScene.ts        전투 승리 보상(카드 3장 중 택1 또는 건너뛰기)
│   ├─ EventScene.ts         사건: 선택지 → 결과
│   ├─ RestScene.ts          내 방: 체력 회복 또는 카드 강화
│   ├─ ShopScene.ts          편의점: 카드 구매 · 카드 정리(제거)
│   ├─ ChapterClearScene.ts  1장 클리어 화면
│   └─ RunEndScene.ts        패배 화면
└─ game/                     Phaser를 전혀 참조하지 않는 순수 규칙 로직
    ├─ combat.ts              전투 한 판의 규칙(카드/적 행동 → 상태 변화)
    ├─ cards.ts                카드 정의 30종 + 강화 스케일링 + 보상 뽑기
    ├─ enemies.ts              적 정의(일반 4 · 엘리트 1 · 보스 1) + 패턴 AI
    ├─ status.ts / effects.ts  상태 효과(버프/디버프) 계산 + 카드·적 행동 공용 어휘
    ├─ run.ts                  층을 넘나드는 런 상태(덱·체력·용돈·맵 진행도)
    ├─ map.ts                  1장 맵 생성(14층, 단순 랜덤 분기)
    ├─ events.ts                사건 5종
    ├─ shop.ts / rest.ts        상점 판매 목록 · 휴식처 선택지
    └─ rng.ts                   공용 셔플/난수 유틸리티
```

`game/`은 규칙, `scenes/`는 화면이라는 원칙을 전 파일에 걸쳐 지켰습니다. 밸런스를 바꿀 때는 `game/` 안의 숫자만 건드리면 됩니다.

## 지금까지 구현한 범위 (Level 0 ~ 5)

- **전투**: 플레이어/적 HP·방어도, 에너지, 드로우/버린/제외 더미, 카드 3종(공격·스킬·파워), 다단 히트, 카드 강화(+30% 수치, 자동 계산), 버프/디버프 6종(기합·유연함·위축·빈틈·잔소리·정색) + 영구 능력치 3종(근성·홈트 루틴·잔소리 체질)
- **적**: 일반 4종 · 엘리트 1종 · 보스 1종, 모두 2~4개 행동을 정해진 순서로 반복하는 결정적 패턴(다음 행동이 항상 미리 보임)
- **런**: 체력·덱·용돈이 층 사이에 그대로 유지되고, 최고 도달 층이 `localStorage`에 남는다
- **맵**: 14층, 1층은 항상 전투로 시작, 13층은 항상 휴식, 14층은 항상 보스. 그 사이는 층마다 2개(엘리트 등장 층은 엘리트 포함 2개)의 무작위 선택지
- **사건 5종 · 상점(카드 구매/정리) · 휴식처(회복/강화)**: 각각 런 상태를 바꾸는 선택지 제공
- **덱빌딩 빌드 3갈래**: 다중 공격(간지럼 러시류), 방어 후 반격(정색/팔짱 끼기류), 잔소리 누적(상태이상 스택류)

## 의도적으로 아직 없는 것 (Level 7~8 이후)

정식 아트(픽셀아트 등), 사운드·배경음악, 화면 흔들림·데미지 숫자 같은 연출, 카드 드래그, 계정·클라우드 저장, PWA, 장비/포션류 아이템, 2~4장 콘텐츠. 새 아이디어는 여기서 바로 구현하지 않고 `IDEAS.md`에 쌓습니다.

## 검증 방법

Phaser 규칙을 전혀 모르는 상태에서도 `game/` 폴더의 각 모듈은 순수 함수라 타입체크(`npm run build`)만으로 회귀를 상당 부분 잡습니다. 화면 쪽은 헤드리스 브라우저로 맵→전투→보상→사건→휴식→상점→보스→챕터 클리어/패배까지 전 구간을 자동 클릭으로 왕복시켜 확인했습니다. `main.ts`가 개발 편의를 위해 `window.__game`에 Phaser 게임 인스턴스를 노출해 두므로(런타임 규칙에는 관여하지 않음), 브라우저 콘솔이나 자동화 스크립트에서 `window.__game.registry.get('run')`으로 현재 런 상태를 직접 들여다볼 수 있습니다.

## 배포

Vite 빌드는 상대 자산 경로를 사용하므로 `/code/game/` 같은 GitHub Pages 하위 경로에서도 작동합니다. 저장소의 Pages 워크플로우가 이 폴더를 빌드해 `dist/`만 `/code/game/`에 게시합니다(현재는 `main` 브랜치로 머지되어야 배포됩니다 — 저장소 Pages 환경 보호 규칙 때문).
