# 운동일지 · 2.2.0-performance-flow

순수 HTML/CSS/브라우저 ES 모듈로 구성된 개인 운동 PWA입니다. 앱의 빌드 단계나 외부 UI 라이브러리는 없습니다. 운동 계획·실행·기록은 기기에 저장하며, AI 계획을 요청할 때만 명시한 최근 기록과 설정을 선택한 AI 제공자에게 보냅니다.

이 수정판은 사용자가 제공한 **fc9981a 소스 번들**을 바탕으로 만들었습니다. 현재 GitHub HEAD나 운영 기기를 확인해 만든 배포 완료판이 아닙니다. 기존 아이콘과 `audio/ko-user/*.mp3`는 변경하지 않습니다.

## 달라진 실행 방식

현재 종목 / 웜업·본세트 / 무게×목표 / 카운트 / 다음 세트가 별도로 표시됩니다. 세트 종료 뒤 실제 수행값을 확인해야 기록됩니다. 자동 카운트는 센서 측정이 아니므로 목표에 도달했다는 이유만으로 실제 수행을 확정하지 않습니다. RIR(몇 회 더 할 수 있었는지)은 선택 사항이며 모르면 자동 증량을 보류합니다.

휴식은 웜업 사이, 마지막 웜업에서 본세트로, 본세트 사이, 운동 사이, 다음 운동 기구 준비, 시작 카운트다운으로 분리합니다. 운동 사이 휴식은 본세트 휴식을 **대체**하며 준비시간만 그 뒤에 더합니다. 같은 종목 자동 시작과 다음 종목 자동 시작은 별도 설정입니다.

편집창·목록·종료 확인을 열거나 화면을 가리면 일시정지합니다. 닫았다고 자동 재개하지 않으며 **이어하기**를 눌러야 합니다. 0초 카운트 대신 수동 카운트가 있습니다. 플랭크처럼 시간을 유지하는 운동은 초로 표시합니다.

## 기록·저장

저장 중량은 kg 고정입니다. lb는 입력·화면 표시에서 변환합니다. 구버전에서 lb를 사용한 기록은 당시 변환 없이 숫자만 표시됐을 수 있어, 사용자가 원래 단위를 선택하기 전 추천을 잠급니다.

IndexedDB의 기존 `workout-log` / `kv`는 유지합니다. v2는 `snapshot.v2` 단일 스냅샷을 쓰며 localStorage `wl:snapshot.v2`를 동기 미러로 기록합니다. revision이 높은 사본을 읽습니다. 기존 v1 개별 키는 자동 삭제하지 않습니다. 서로 다른 v1 사본, 손상된 값은 자동 초기화하지 않고 복구 화면으로 보냅니다. 사용자가 오류 화면에서 명시적으로 확인한 경우에만 `reset.html`이 workout 소유 DB와 `wl:` 저장값을 지우고 검증한 빈 v2 snapshot을 만듭니다. 독서앱 저장소와 캐시는 건드리지 않습니다.

진행 중 세션을 저장하고 재실행하면 **이어하기 / 여기까지 저장 / 폐기**를 선택합니다. 기기에 실제 저장하지 못하면 실패 배너와 재시도·메모리 백업을 제공합니다. 어떤 웹앱도 사용자의 브라우저 데이터 삭제, 디스크 손상, 저장 직전의 운영체제 종료까지 모두 방지하지는 못하므로 외부 JSON 백업이 필요합니다.

복원은 **합치기 / 덮어쓰기 / 취소**입니다. 닫기·배경·Escape는 취소이며, 덮어쓰기는 별도 확인 뒤 실행합니다. 전체 형식 검증이 성공하기 전 활성 데이터를 바꾸지 않습니다. 정상 백업은 API 키·프록시 토큰을 제외합니다. **복구용 원본에는 키가 포함될 수 있으니 공유하지 마세요.**

## 주간 계획과 추천

요일 배치·기구·제외 종목·목표·경험을 먼저 정합니다. 주간 부위별 본세트 목표는 운동시간, 운동일, 부위 빈도와 하루 종목 수에서 자동 계산하며 카운트·휴식·기구 전환을 포함한 시간 예산을 넘으면 세트부터 줄입니다. 각 부위는 수동 목표로 바꾸거나 다시 자동 추천으로 돌릴 수 있습니다. 2.1의 옛 기본값은 자동 추천으로 전환하고, 사용자가 기본값과 다르게 저장한 값은 수동값으로 보존합니다. 같은 날 중복 종목을 넣어 부족한 후보를 메우지 않습니다. 주요 종목 유지 모드와 기존 매주 로테이션 모드를 모두 제공합니다. 기존 사용자의 로테이션 선택은 마이그레이션에서 유지합니다.

운동 실행 화면에는 현재 종목의 남은 세트만 건너뛰는 **이 운동 그만하기**와, 완료 기록을 `partial`로 원자 저장한 뒤 종료하는 **오늘 운동 그만하기**가 분리되어 있습니다. 둘 다 확인 뒤 실행하며 자동 기록 대기와 타이머를 먼저 중지합니다.

기록 상세의 세트 행은 중량·횟수·RIR·확인에 집중하고 자동 진행으로 저장된 미확인 값은 작은 `자동` 배지로만 구분합니다. 하단 내비게이션은 이모지나 자동차 브랜드 자산 없이 추상적인 그릴·시동·계기판 감성의 독자 SVG 선형 아이콘을 사용합니다.

본세트 전체의 실제 목표 달성, RIR, 최근성, 중단 여부, 실제 기구 단계, 상대 증가율을 보고 유지·증량·확인 필요를 구분합니다. 타 종목 환산은 낮은 신뢰도의 시작 추정값이며 알 수 없는 사용자 종목은 임의 환산하지 않습니다. 웜업도 이미 준비한 동작, 기구 단계·최소 중량을 반영합니다.

**목표량, 비율, 웜업 단계는 변경 가능한 앱 정책이며 개인별 운동 처방이 아닙니다.** 실제 수행과 기구를 확인해 수정하세요. 직접 본세트와 보조 자극을 동일한 양으로 합산하지 않습니다. 웜업·시간 운동·기록 표기중량 볼륨을 구분합니다.

## AI: OpenAI / Claude

`proxy/README.md`대로 개인 Worker를 배포하면 설정에서 두 제공자를 선택할 수 있습니다. OpenAI는 Responses API, Claude는 Messages API를 사용하며 서버·브라우저가 같은 출력 계약을 검사합니다. 생성 결과는 **미리보기 → 명시적 적용**을 거칩니다. 생성·키 확인을 자동 호출하거나 유료 생성 요청을 자동 재시도하지 않습니다.

제공자 API 키는 Worker secret에만 넣습니다. 앱에 입력하는 접속 토큰은 제공자 키가 아니라 이 개인 프록시만 호출할 수 있는 별도 값입니다. 토큰은 `sessionStorage`에만 보관하며 탭을 닫으면 사라집니다. 이전 버전이 브라우저에 저장한 제공자 API 키는 v2 초기화 때 workout 전용 저장소에서 제거합니다. 브라우저에서 OpenAI/Anthropic API를 직접 호출하는 경로는 제공하지 않습니다.

비용을 고정 원화 금액으로 추정하지 않습니다. 응답 사용량 토큰을 표시하고 실제 청구는 제공자 계정에서 확인합니다.

## 실행·배포

저장소 루트에서 `python -m http.server 8123`를 실행하고 `/workout/index.html`을 엽니다. GitHub Pages에는 기존처럼 정적 파일을 배포합니다. 실제 iPhone에서는 HTTPS 주소를 Safari로 열어 홈 화면에 추가합니다. **기록이 있는 앱을 삭제하거나 Safari 데이터를 지우지 마세요.**

서비스워커는 네트워크 우선, HTTP 캐시 우회, 앱 경로·자기 캐시 접두사만 정리하도록 구성했습니다. 필수 모듈을 모두 확보하지 못하면 새 서비스워커 설치는 실패하고, 없는 JS에 HTML을 돌려주지 않습니다. 상대 앱 캐시는 지우지 않습니다. 배포 중 연결 단절·기기별 설치와 오디오 허용 동작은 실제 기기 확인이 필요합니다.

## 코드 구조

- `config.js` 기본 정책, `validation.js` 입력·백업 검증
- `persistence.js` 스냅샷 쓰기, `store.js` 마이그레이션·복원·진행 기록
- `exercises.js` 종목·동작·측정 방식, `weights.js` 중량·웜업, `timing.js` 공통 시간 계산
- `planner.js` 규칙 생성·계획 평가, `ai-contract.js` 공통 AI 계약, `ai.js` 호출
- `runner.js` 실행 상태와 유일한 세트 원본, `voice.js` 취소 가능한 클립·TTS
- `ui.js` 안전한 DOM·모달, `views/` 화면, `stats-model.js` 통계 계산

배포 전에 동봉 테스트와 별도 설치 안내를 확인하세요. 실제 API 호출·Cloudflare 배포·아이폰 Safari 실기기 검증은 이 패키지의 자동 테스트와 별개입니다.
